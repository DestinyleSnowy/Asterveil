# Asterveil

面向 7FA4 的模块化浏览器扩展，提供页面美化、主题与深浅色切换、本地抽象头像、首页加载优化和外站提交器。

公开仓库：[DestinyleSnowy/Asterveil](https://github.com/DestinyleSnowy/Asterveil)。

配置支持 `https://jx.7fa4.cn:8888/` 与 `https://in.7fa4.cn:8888/`，两个入口共用本地设置。外网入口已成功访问；内网入口当前返回 `ERR_CONNECTION_CLOSED`，实际内网运行仍待验证。浏览器以 Chrome / Edge 120+ 的 Manifest V3 为当前目标；尚未验证 Firefox。

## 开发与加载

需要 Node.js 22.12+ 和 npm。

```sh
npm ci
npm run dev
```

开发模式由 WXT 管理。构建正式产物：

```sh
npm run check
npm run build
npm run zip
```

在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 中开启开发者模式，选择“加载已解压的扩展程序”，加载 `.output/chrome-mv3`。安装后刷新已打开的目标网站页面。`npm run zip` 生成用于分发的 ZIP，不会发布到商店。

设置通过网站右下角的圆形星芒按钮打开，分为“外观配色”“功能模块”和“关于”，三个页面采用统一的卡片布局。“关于”提供总开关、版本、作者、许可证与项目链接。暂停后仍可打开设置，支持关闭按钮、Esc 和点击面板外部关闭。工具栏 Asterveil 图标打开 7FA4 Submitter 提交器。

设置静默保存，不显示保存提示或界面预览。面板开合、分类切换、配色与开关提供短时过渡；系统开启“减少动态效果”时取消动画。深浅色和窄屏布局均适配。

## 外站提交器

整合 7FA4 submitter 0.1.13，来源与移植说明见 [第三方来源](THIRD_PARTY_NOTICES.md)。

弹窗沿用 Asterveil 的星形标识、圆角和所选主题色，只显示操作按钮、登录状态与版本。

1. 在已登录的 7FA4 页面点击 Asterveil 图标，选择“更新 7FA4 登录信息”。
2. 打开外站的提交记录详情，确保评测完成且完整源代码已显示。
3. 点击“发送提交”。在 vjudge 页面，此操作会尽可能转换为原站题号；“发送提交 · vjudge 题号”保留 vjudge 的题号。

保留原提交器对洛谷、UOJ、QOJ、Codeforces / Gym、AtCoder、vjudge、CodeChef、CSAcademy、正睿、信友队、OIFHA、MNA 和 7FA4 的解析适配。解析依赖外站页面结构，各外站后续改版可能需要更新选择器。沿用原提交器的 `cpp17` 上报字段。没有完整代码、题号或评测结果时不会发送；网络超时后先核对 7FA4 的提交记录，避免重复提交。

提交目标沿用压缩包列出的 7FA4 域名、端口及两个 IP 入口，使用更新登录信息时选中的入口。该入口单独保存在本地，不复制 Cookie、localStorage 或 sessionStorage，不从旧插件迁移登录数据。提交器为点击触发的独立工具，不随网页美化开关停用。上游版本标记为整合时的版本，不再通过上游 VERSION 文件判断 Asterveil 是否需要更新。

- **界面微调**：默认开启，覆盖首页、学习、模测、评测、进度、外站、计划、奖励记录及个人主页。统一背景、圆角、边框、导航选中态与表格间距，保留原有页面结构和状态色。学习表头补齐顶部留白；计划页区分周计划、突出今天，可拖动的悬浮日期目录支持点击跳转并随已加载日期更新，不占表格空间，默认居中放在浏览器左边缘与列表左边缘之间；个人主页整理头像和信息卡片。关闭时移除样式、计划辅助控件及当天标记，恢复根节点属性。
- **主题配色**：七项依次为雾蓝、松绿、鸢紫、蔷薇、琥珀、岩灰和自定义；自定义使用系统选色器。颜色保存后自动更新已打开的适用页面，两个入口共用；暂停扩展或关闭界面微调会保留选色。浅色会自动生成更深的文字强调色，使其在导航底色上的对比度至少达到 4.5:1；题目状态色不受影响。
- **显示模式**：“外观配色”中可选浅色、深色和跟随系统，与主题色独立保存。旧设置默认浅色；跟随系统会即时响应系统切换。适配页面、右下角设置及提交器弹窗共用模式，图片和图表保留原色，深色代码区使用可读的语法高亮，打印使用浅色。关闭界面微调会恢复网站外观，设置面板仍可切换模式。
- **键盘焦点**：默认关闭，开启后可用 Tab 键检查轮廓，关闭后会移除对应样式。
- **本地头像**：默认开启，阻止两个 7FA4 入口向 Gravatar 官方域名及 `gravatar.loli.net` 镜像发送头像图片请求，用本地生成的抽象几何 SVG 图案替换。相同头像标识保持同一样式，支持异步新增、延迟加载和响应式图片；不请求其他头像服务。关闭该模块或总开关会取消拦截并恢复头像属性。
- **首页加速**：默认开启，为同入口首页大图添加异步解码和加载优先级提示；桌面首页的独立卡片在首次测量实际高度后减少屏外渲染，保留原图、表格和业务请求。窄屏与打印使用正常渲染。头像模块在设置就绪后即可随 HTML 解析替换图片，不再等待 DOMContentLoaded。所有优化随扩展打包，内网无需访问公网，外网也继续拦截 Gravatar。

题目详情 `/problem/:id` 和评测详情 `/submission/:id` 共用所选主题。题目页整理标题、限制标签、操作按钮、题面章节和样例区；评测页整理结果表、代码区、格式化按钮与测试点折叠面板。保留公式、原始代码、状态色和原有交互，不修改编辑器内容或执行提交。仅匹配明确适配的页面，不对编辑、下载等其他子路径应用样式。

模测详情 `/contest/:id` 同样应用主题，整理标题标签、时间栏、操作按钮和题目表格，保留比赛进度及状态颜色。模测内的题目 `/contest/:id/problem/:id` 复用题目详情样式。

模测和题目详情页的操作按钮保留网站原配色及悬停、按下状态，仅调整圆角、间距和阴影。

批改页 `/problem/:id/answers/...`、投稿页 `/problem/:id/suggestion` 与统计页 `/problem/:id/statistics/...` 也共用主题。批改页整理答案与评价卡片；投稿页整理动态表单与审核列表；统计页整理排序菜单、提交表格与图表容器。保留原有评分状态和字段显示逻辑，不代替用户执行评价或投稿。

用户名菜单中的修改资料、我的榜单、登录凭证、参赛资料、上课表格、我的申请、提交打印、我的好友、RPGainer、签到情况、投稿更正和帮助页面也应用主题，保留表单及状态颜色。聊天不在适配范围内；切换账号、注销和凭证下载不做操作。

计划日期条默认延伸至窗口下方，可拖动上下边缘调整高度，顶部“日期”用于移动；不显示额外的拖动图标。表头在实际滚动容器顶部固定，不再重复叠加导航栏偏移。

页面主题在 `document_start` 阶段初始化，先读取本地配色再显示适配页面；目录、设置面板等 DOM 功能在节点就绪后挂载。读取失败立即恢复显示，异常长时间未返回则最多等待 800ms 后恢复，避免页面一直隐藏。原站布局样式继续加载，Asterveil 提前覆盖配色。切换主题仅更新颜色变量，不重建计划目录。

更新构建后，在扩展管理页重新加载 Asterveil，再刷新网站。旧设置会自动补齐新模块的默认值及雾蓝配色，保留总开关和已有模块偏好。此后切换配色不需要刷新页面。

## 添加模块

1. 在 `src/shared/catalog.ts` 添加 ID、标题、描述和默认开关。
2. 在 `src/features/<name>/index.ts` 实现 `FeatureModule`。
3. 在 `src/features/registry.ts` 注册路径匹配器与加载函数；设置面板自动生成开关。
4. 将站点专用的选择器和页面识别放入 `src/site/`，基于实际 DOM 编写，不依赖猜测。

模块必须为创建的资源注册清理，并在异步任务中使用 `scope.signal`。例如：

```ts
import type { FeatureModule } from '../../core/module';

export default {
  mount({ scope }) {
    const node = document.createElement('aside');
    scope.defer(() => node.remove());
    document.body.append(node);
    node.addEventListener('click', () => {}, { signal: scope.signal });
  },
} satisfies FeatureModule;
```

新增模块不需要修改运行时或后台。需要修改网页原有属性时，应保存旧值并在清理时恢复。新增复杂浮层应使用 Shadow DOM 隔离；不要对整站应用 CSS reset。

## 权限与数据

正式构建声明 `storage`、`activeTab`、`scripting`、`declarativeNetRequest` 权限，并申请提交目标的精确主机权限。`declarativeNetRequest` 用于限定站点来源的 Gravatar 头像拦截。美化内容脚本仍只匹配两个精确主机名，在运行时检查 HTTPS 和 8888 端口。提交器仅在点击发送时读取当前支持页面的 HTML，在弹窗中解析；只把代码、题号、结果等提交字段发往选中的 7FA4 `/foreign_oj`。后台通过 `/user_api/json` 检查登录，网络请求携带浏览器现有会话，不读取或保存 Cookie，也不记录源代码日志。

没有 `<all_urls>` 内容脚本、跨框架注入、全站 jQuery 注入或远程代码加载。设置与提交目标在 `browser.storage.local` 中使用独立键保存；卸载扩展会删除这些设置。会话请求依赖 Chrome 的[扩展主机权限与 Cookie 行为](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)，浏览器阻止第三方 Cookie 时可能需要调整对应站点的浏览器设置。

`package.json` 的 `private: true` 用于防止意外发布 npm 包，与 GitHub 仓库公开性无关。

类型检查与生产构建已通过。上述外网页面已使用真实功能代码进行浏览器预览，检查了设置开关、换色、分类、关闭后焦点恢复、320px 窄屏面板、动画及减少动态效果、计划定位及清理。预览模拟扩展消息和存储，不等同于真实扩展安装后的端到端验收；跨标签同步与内网仍需在实际安装环境验证。

验证记录见 [架构文档](docs/architecture.md)。按项目要求，不长期保留临时测试脚本或测试依赖；类型检查、格式检查与构建命令保留，便于后续维护。
